Brill HQ — Design Layout Reference

The look and behaviour of HQ Tasks — the Brill HQ workspace app (index.html): tasks, projects, long notes, files, reminders and the assistant. Every token, pattern and rule on this page is lifted from the running app. Use it as the source of truth when adding a view, a row type, a control or a state.

Ratio guide: ~90% white and warm-gray neutrals · ~8% ink text · ~2% blue. There is one accent (blue) and it means "action or on": Add, checked, focused, link, progress. Red means "destructive or urgent". Amber/yellow means "medium / paused / waiting". Green means "active / on track". Nothing else is coloured — hierarchy comes from the three gray text levels, not from colour.

Font stack: ui-sans-serif, -apple-system, BlinkMacSystemFont, "Segoe UI", Helvetica, Arial — the platform font, never a web font. Weights: 400 body · 500 nav & pills · 600 current/selected, labels, buttons · 700 titles only. Uppercase + tracking is reserved for section and group labels. Emoji stand in for icons everywhere (☑ 📁 📝 📎 ⏰ 💬 📅 ⚙️ 🔍).

Shape & elevation

Radii — rows, nav items, small buttons 6px (--radius) · inputs, quick-add, menus, delete bar 8px · cards, modals, info panels 10px · search modal, login card, drop zone 12px · chat composer, bubbles 14px · chips (group input, chat chips) 12px pill-ish · checkboxes 3–4px.
Borders — hairline rgba(0,0,0,.08) for dividers and cards; .14 for anything you type into or press. No coloured borders except blue on focus and red on the delete bar.
Shadow — flat by default. Only floating things get --shadow-card (menus, modals, search); cards get a whisper 0 2px 10px rgba(15,15,15,.07) on hover. Toast: 0 5px 15px rgba(15,15,15,.2).
Focus — border-color: var(--blue) + box-shadow: 0 0 0 3px var(--blue-soft) on every focused container.
Rhythm — content column max-width: 820px (1240px for the card grid), padded 56px 48px 120px (24px 16px 90px on mobile). Rows are 6–10px tall-padded and touch; whitespace, not lines, separates them.

6 · Inputs & buttons

Quiet until focused

Buttons — small, mostly text

+ Upload

Primary is the only filled button: blue, white 600 text, 6px radius (10px in the chat composer, 8px on login). One per surface — the quick-add's Add, a modal's confirm, Send. Secondary (.new-btn): white with a .14 border, 13px/500. Destructive: solid red only in the delete bar; everywhere else red arrives on hover (.icon-btn.danger, .danger-link). Icon buttons are 12px faint text with a 4px hover fill — the row-level verbs (Note · → Project · Edit · Archive · ✓ Done · ✕). Links in prose and file names are blue.

Text inputs — borderless where they can be

🔍
⏰

Two families. Bordered containers (quick-add, search, modal fields, composer): .14 border, 8px radius, and on :focus-within the border goes blue with a 3px --blue-soft ring — the input inside has no border of its own. Bare inputs (titles, project notes, card add, property selects): no border at all, transparent, they read as text until you click. The notes textarea is the exception — a sidebar-gray box with a hairline that turns blue on focus. Placeholders are --faint (titles: #d4d2cc). Selects inside inputs are gray chips (--sidebar fill, 13px muted).

10 · Rules of the look

Do · Don't

Do

  • Build every view as title → subtitle with counts → one quick-add row → tabs/controls → sections of rows.
  • Use the three text grays (text / muted / faint) for hierarchy; use blue only for "action" and "on".
  • Let rows touch and show a --hover fill; reveal row actions on hover (always on touch).
  • Make titles and notes editable in place — an input styled as text, saved on blur or Enter.
  • Keep pill meanings fixed: green Active, yellow Paused/medium, gray Done/low, red high/Due now, blue cadence.
  • Put bulk and destructive actions behind the ⋯ menu; confirm deletes with the red delete bar.
  • Focus with the blue border + 3px soft ring on the container, never an outline on the input.
  • Use an emoji as the icon; 6px radius on rows and small controls, 8px on inputs, 10px on cards.
  • Confirm quiet actions with the dark toast; keep counts live in the sidebar and subtitles.

Don't

  • Don't add colour for decoration — no coloured headings, no tinted sections, no gradients, no dark mode.
  • Don't put more than one filled blue button on a surface, and never a red one outside delete mode.
  • Don't box rows in cards or add borders between task rows; hairlines are for reminders, files and project lists only.
  • Don't introduce a web font, a new gray, or a new pill colour (purple is reserved).
  • Don't use uppercase outside section and group labels; don't use bold outside titles, current items and buttons.
  • Don't use shadows on things that don't float; only menus, modals, search and the toast cast one.
  • Don't add a separate edit screen or a Save button — everything saves itself.
