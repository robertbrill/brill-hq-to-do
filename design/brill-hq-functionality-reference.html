🔒 Privacy is Row-Level Security, not secrecy. Every table has an own_all policy (user_id = auth.uid()) and the uploads bucket the same rule on owner. The anon key in config.js is public by design. The base task list, which contains real names and numbers, is never a static file — it comes from /api/base-tasks only after the token checks out.

2 · Sign-in, startup & sync

Auth gate · Load order · Polling

The auth gate

HQ Tasks

Sign in to your Brill HQ workspace.

Invalid login credentials

The app stays hidden until a Supabase session exists. Email + password via BrillDB.signIn; sessions persist and auto-refresh. A missing or placeholder config.js shows a "Not configured" card instead. A null session that isn't an explicit sign-out does not reload the app.

Startup order

1 · loadAllprojects, to-dos, notes, task overrides — one snapshot
2 · loadInbox + loadBaseTasksthe quick-add rows and the token-gated base list
3 · loadReminders · push · SMS statewhat's scheduled and which channels this device has
4 · routeInboxItemsfile any inbox row that names a project (see § 3)
5 · renderrestore last view, last project, collapsed sections, groups nav from localStorage

Saving and staying in sync across devices

Any editqueueSave() marks state dirty; after a short debounce the whole snapshot goes to BrillDB.saveAll. The saved payload is remembered so it isn't synced back.
→
Every 12 s + on tab focusmaybeSyncState() reloads; if the payload differs, another device changed data and this one adopts it. Skipped while dirty or while you're typing, so a re-render never steals the caret.
→
Every 10 sthe inbox is re-read so tasks from the assistant, the CLI or another device appear without a refresh.
→
Every 30 sreminders reload, a pending SMS enrollment is re-checked (picks up the YES reply), and due reminders are delivered in-app.

Re-renders keep an open notes box and its caret in place. The notes pane has opt-in diagnostics (?noteDebug in the URL) that survive a reload and record what caused one.

How a reminder gets delivered

Addtitle · date-time · repeat. Set for "now" → delivered immediately. Pending = fired_at null.
→
App open (every 30 s)due rows show a toast + browser notification. If no push or SMS channel is enrolled, the app marks it delivered (fired_via: app) or advances a repeat to its next occurrence.
→
App closed (cron, every minute)/api/send-reminders with the service-role key finds due rows across users, pushes to every device, texts a confirmed number, marks delivered; repeats advance instead. Dead subscriptions are pruned. No channel → the row stays pending for the app.
→
Tapsw.js focuses or opens the app on the Reminders view. ✓ Done dismisses · ⏲ +1h snoozes · ✕ deletes.
ChannelEnrolStates
Web PushEnable notifications on this device → permission prompt → registers sw.js → subscribes with the server's VAPID key → saves the subscription. iPhone: add to Home Screen first.unsupported · denied · off · on (with device count). Turn off removes this device only.
SMS (Twilio)Enter a number, tick consent, Send confirmation → number saved as pending → reply YES → confirmed. Double opt-in; the browser can never mark a number confirmed itself.off → pending (Resend · Refresh) → confirmed (Stop). STOP at the carrier blocks the number; only START / UNSTOP undoes it. HELP is answered by Twilio.
RepeatOnce · Daily · Weekdays · Weekly · Monthly (same day-of-month, clamped to the month's last day).Advances to the next occurrence strictly after now on each delivery.

The round trip

Browserposts the chat history (≤ 24 turns, ≤ 8k chars each) + context: local time and zone, project names, note titles and groups, pending reminders, open inbox count. Bearer = the user's access token.
→
/api/assistantverifies the token, calls Claude with a fixed system prompt and six tools, returns a one-or-two-sentence reply plus the tool calls. It never touches the database.
→
Browser applies the actionsthrough BrillDB with the user's own session, so Row-Level Security still governs every write. Each result becomes a chip (✓ opens what it created; ✕ explains the failure).
ToolInputsWhat the app does
add_tasktext · priority · project? · notes?No project → inbox row. With a project → filed into it (created if missing) under AI Projects.
create_projectname · notes? · status? · due? · owner? · todos[]?Creates (or updates an existing name) and seeds the to-dos in order.
create_notetitle · body (Markdown) · group?New long note; Markdown → the note's HTML (paragraphs, bullets, numbered, - [ ] checklists, ## headings).
append_to_notenote_id · textAppends to the named note.
set_remindertitle · due_at (ISO with offset) · notes? · repeat?Adds a reminder; never in the past (a passed time rolls to tomorrow and says so).
cancel_reminderreminder_idDeletes a pending reminder.

Rules baked into the prompt: act without asking unless something essential is missing · match existing project and note names case-insensitively · "tomorrow morning" = 9:00, "afternoon" = 14:00, "evening" = 18:00, "tonight" = 20:00, "end of day" = 17:00, a bare day = 9:00 · priority from wording (ASAP / today → urgent, this week / important → high, someday → low) · a task and a reminder are separate; do both if asked. The 🎤 button dictates where the browser supports speech recognition. The conversation persists in localStorage; needs ANTHROPIC_API_KEY on the server (503 and a yellow notice otherwise).

10 · Server functions & mobile

Vercel · Supabase · Twilio · ≤ 760px
FunctionAuthPurpose
GET /config.jsnonePublic config from env: Supabase URL and anon key, VAPID public key, whether SMS is on.
GET /api/base-tasksuser tokenThe base task list. Contains real names and numbers, so it is never a static file.
POST /api/assistantuser tokenChat → actions. Needs ANTHROPIC_API_KEY; ASSISTANT_MODEL optional.
GET /api/send-remindersCRON_SECRETEvery minute. Needs the service-role key plus VAPID keys and/or Twilio credentials.
POST /api/sms-optinuser tokenstart / resend (60 s cooldown) / stop. State lives in the user's app_metadata.sms, writable only with the service role.
POST /api/sms-inboundTwilio signatureYES / START / UNSTOP confirm · STOP family records the opt-out · HELP left to Twilio · anything else gets a pointer to the app.

Every user-token function goes through lib/verify-user.js, which checks the bearer token against Supabase and fails closed. The service worker (sw.js) only handles push and notification clicks; it caches nothing, so deploys are never stale. todo-data.js and todo-v2.html (the Mac edition) are excluded from deploy. add-todo.sh is that edition's CLI: add-todo.sh "task" [priority] [project] [notes].
